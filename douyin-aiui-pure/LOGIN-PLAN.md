# 抖音网页版扫码登录接入方案

## 目标和边界

在纯 AIUI 中展示抖音网页版登录二维码；用户用手机抖音扫码并确认，AIUI 接收并维护网页会话。未登录时继续匿名播放。此方案属于网页会话接入实验，不是第三方 OAuth 授权，不以开放平台应用和自建授权回调服务为必要前提。

## 当前证据

开源代码包含 SSO get_qrcode、check_qrconnect 和确认后跟随重定向收集 Cookie 的流程。这是实现线索，不代表接口目前稳定可用。

2026-11-02，本机通过 Python 标准库、浏览器风格 User-Agent 和 Referer 直接请求 sso.douyin.com/get_qrcode/，返回 HTTP 200、text/html、10168 字节，非 JSON，未取得二维码或 token。尚未确认页面具体内容与失败原因，不能推导所有客户端均失败。

## 实施顺序及验证门槛

1. 首先验证当前 Ink 原生网络能否取得真实二维码及短期会话标识；核对当前网页实际参数和 Cookie。若要求浏览器执行或交互验证，记录与纯 AIUI 的兼容限制，不假定匿名推荐成功就意味着登录接口也可用。
2. 取得二维码后，以 AIUI 图片组件展示并受控轮询；用户手机确认后，仅跟随经过核实的抖音登录回调域名，按域、路径和有效期处理 Cookie。轮询状态码需以实际响应确认。
3. 用账号状态接口验证已登录，测试会话失效、退出、账号切换和重启恢复。Cookie 不打印、不打包进 AIX；持久化前确认宿主可用的安全存储能力。
4. 把作用域匹配的登录 Cookie 用于现有推荐请求，核对响应和播放。账号个性化效果需另行对照，不能凭请求成功就宣称成立。
5. 接入 onVoiceWakeup；未登录展示二维码，已登录继续播放。取消、失效和取码失败时允许匿名观看。实机核验唤醒分发、关闭后停止轮询及在途请求隔离。

## 状态

方案已明确；取码、扫码确认、会话落地、登录后推荐均尚未完成端到端验证。第一道门槛是从 Ink 取得有效二维码。
