# 抖音网页版扫码登录接入方案

## 目标和边界

在纯 AIUI 中展示抖音网页版登录二维码；用户用手机抖音扫码并确认，AIUI 接收并维护网页会话。未登录时继续匿名播放。此方案属于网页会话接入实验，不是第三方 OAuth 授权，不以开放平台应用和自建授权回调服务为必要前提。

## 当前证据

开源代码包含 SSO get_qrcode、check_qrconnect 和确认后跟随重定向收集 Cookie 的流程。这是实现线索，不代表接口目前稳定可用。

2026-11-02，本机通过 Python 标准库、浏览器风格 User-Agent 和 Referer 直接请求 sso.douyin.com/get_qrcode/，返回 HTTP 200、text/html、10168 字节，非 JSON，未取得二维码或 token。尚未确认页面具体内容与失败原因，不能推导所有客户端均失败。

## 实施顺序及验证门槛

1. 首先验证当前 Ink 原生网络能否取得真实二维码及短期会话标识；核对当前网页实际参数和 Cookie。若要求浏览器执行或交互验证，记录与纯 AIUI 的兼容限制，不假定匿名推荐成功就意味着登录接口也可用。
2. 取得二维码后，以 AIUI 图片组件展示并受控轮询；用户手机确认后，仅跟随经过核实的抖音登录回调域名，按域、路径和有效期处理 Cookie。轮询状态码需以实际响应确认。
3. 用账号状态接口验证已登录，测试会话失效、退出、账号切换和重启恢复。Cookie 不打印、不打包进 AIX；持久化前确认宿主可用的安全存储能力。
4. 把作用域匹配的登录 Cookie 用于现有推荐请求，核对响应和播放。账号个性化效果需另行对照，不能凭请求成功就宣称成立。
5. 接入 onVoiceWakeup；未登录展示二维码，已登录继续播放。取消、失效和取码失败时允许匿名观看。实机核验唤醒分发、关闭后停止轮询及在途请求隔离。

## 状态

方案已明确；取码、扫码确认、会话落地、登录后推荐均尚未完成端到端验证。第一道门槛是从 Ink 取得有效二维码。

实现线索：https://github.com/Axbros/douyinLogin/blob/main/getLogin.py

## 当前实现与验证（2026-11-02）

- 已接入 `onVoiceWakeup`，未登录时打开取码弹层；已登录时不重复发起登录。也可点击页面左上角的“扫码登录”；Mac 键盘 L 可触发同一路径。
- 支持二维码 PNG 展示、两秒一次的状态轮询、三分钟本地超时、取消/过期/错误和退出登录。关闭、隐藏和卸载页面会清理轮询并取消在途登录请求；过期返回不会恢复弹层或登录。
- 仅在可信 HTTPS 回调完成、收到可用于主站的会话 Cookie、且账号接口返回账号标识后标记登录成功。登录成功后清空旧队列并使用会话 Cookie 请求现有推荐接口。拒绝自动跟随带凭证的推荐请求重定向；取消或切换会话会隔离旧请求结果。
- Cookie 按域、路径、有效期处理；凭证和二维码 token 仅保存在运行时内存中，不写入 localStorage，不进入 AIX 或应用日志。页面重建/进程退出后需要重新登录；安全持久化尚未实现。退出只清理当前播放器会话，不代表服务端撤销所有设备会话。
- Mac Ink 真实请求：主站 passport 取码接口 HTTP 200、`data.error_code=4031`，无二维码。另以本机标准 HTTP 客户端核对该响应说明为“您正在尝试访问的网站存在安全风险，为保护您的抖音账号安全与隐私，已阻止此次访问。”；SSO 后备入口返回 HTML。没有取得真实二维码，也没有绕过该限制。
- Mac 480×352 离屏截图验证了登录失败弹层与匿名继续入口，页面后台匿名推荐请求仍返回 `status_code=0`、2 条视频候选。离屏视频解码有 VideoToolbox 及格式错误，此次不作为播放成功证据。
- 48 项 Node 测试通过（原有 32 项 + 新增 16 项）。扫码成功、回调、登录会话切换等测试使用受控响应；不等同于真实账号登录成功。
- 第一条真实阻塞仍是平台未提供有效二维码。当前接口参数及返回格式需要继续与实际网页协议核对；`qrcode_index_url` 单独返回但没有 PNG 时，当前实现会明确失败，不会擅自把它当图片。Passport 状态兼容分支亦未经真实扫码验证。

Mac 直接进入登录弹层诊断（仍为真实网络请求）：
